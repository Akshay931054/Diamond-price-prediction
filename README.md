# 💎 Diamond Price Prediction

An end-to-end machine learning project that predicts the retail price of a diamond from its physical characteristics and quality grades. It covers data cleaning, exploratory analysis, model comparison, cross-validation, and a reusable prediction function backed by a saved model.

## Overview

Diamond pricing depends on the "4 Cs" (carat, cut, color, clarity) plus physical dimensions. This project trains and compares three regression models on the classic Diamonds dataset (~54,000 records), then saves the best performer for reuse.

**Key features**

- Data cleaning (duplicates, impossible zero dimensions, outliers)
- Seven exploratory charts saved automatically to `charts/`
- Log-transformed target to handle heavily skewed prices
- Scikit-learn `Pipeline` so preprocessing and model travel together
- Ordinal encoding that respects real quality ordering (e.g. `Fair < Good < Ideal`)
- 5-fold cross-validation of the winning model
- Persisted model (`joblib`) with a simple `predict_price()` function

---

## Results

Evaluated on a held-out 20% test set, with errors measured in real dollars (not log-dollars):

| Model             | R²    | MAE ($) |
|-------------------|-------|---------|
| Gradient Boosting | 0.983 | ~271    |
| Random Forest     | 0.982 | ~265    |
| Linear Regression | 0.950 | ~458    |

The tree-based models clearly outperform the linear baseline, which confirms that price has non-linear relationships with the input features. Gradient Boosting and Random Forest are nearly tied; the script automatically selects whichever scores the highest R².

## Getting Started

### Prerequisites

- Python 3.10 or newer
- The Diamonds dataset as `diamonds.csv` (columns: `carat, cut, color, clarity, depth, table, price, x, y, z`)

### Installation

```bash
# 1. Clone the repository
git clone https://github.com/<your-username>/<your-repo>.git
cd <your-repo>

# 2. Create and activate a virtual environment
python -m venv .venv
source .venv/bin/activate        # macOS / Linux
.venv\Scripts\activate           # Windows

# 3. Install dependencies
pip install -r requirements.txt
```

### Configure the dataset path

Open `Diamond prediction.py` and update `DATA_PATH` to point to your local copy of `diamonds.csv`:

```python
DATA_PATH = Path(r"path/to/your/diamonds.csv")
```

## Usage

### Train and evaluate

```bash
python "Diamond prediction.py"
```

This will clean the data, generate all charts, compare the models, run cross-validation, and save `diamond_model.joblib`.

Set `SHOW_PLOTS = False` in the script to save charts without opening pop-up windows (recommended for servers or CI).

### Predict a price

```python
# predict_price() is defined in "Diamond prediction.py" and loads diamond_model.joblib.
# Note: the model file must already exist (run the training script once first).

price = predict_price(
    carat=1.0, cut="Ideal", color="G", clarity="VS1",
    depth=61.5, table=56.0, x_mm=6.4, y_mm=6.43, z_mm=3.95,
)
print(f"Predicted price: ${price:,.2f}")
```

**Valid categorical values**

| Feature | Values (worst to best)                     |
|---------|--------------------------------------------|
| cut     | Fair, Good, Very Good, Premium, Ideal      |
| color   | J, I, H, G, F, E, D                        |
| clarity | I1, SI2, SI1, VS2, VS1, VVS2, VVS1, IF     |

## Methodology

1. **Cleaning:** drop duplicates, remove rows where `x`, `y`, or `z` is 0, and filter extreme outliers (`y`, `z` ≥ 30).
2. **Target transform:** model `log1p(price)` to reduce right skew, then convert back with `expm1` for evaluation.
3. **Preprocessing:** `OrdinalEncoder` with explicit category order for `cut`, `color`, `clarity`; `StandardScaler` for numeric columns.
4. **Modelling:** Linear Regression, Random Forest (200 trees), Gradient Boosting (300 trees, depth 4).
5. **Validation:** 80/20 train-test split plus shuffled 5-fold cross-validation (`random_state=42` for reproducibility).
6. **Persistence:** the full pipeline is saved with `joblib`.

## Known Limitations

- The dataset path is hard-coded and must be edited before first run.
- The script's file name contains a space, which requires quoting on the command line.
- The `predict_price()` function lives in the main script, so importing it re-runs the full pipeline. It should be moved into its own module.
- Models use default or lightly chosen hyperparameters; no systematic tuning has been done.
- The dataset is historical, so predictions do not reflect current market prices.
- `script.py` is an unfinished fraud-detection draft. It references undefined variables (`CAT_COLS`, `ID_COLS`) and is not part of the diamond pipeline.
